产品开发日志 · agentNote 迭代记录

2026 年 9 月 16 日的开发记录：为什么先做首次使用体验，为什么调整 agent 的更新方式与文档结构 —— 一篇关于“先让价值被感知”的产品日志。

成型
agentNote开发日志首次体验

今天我们继续把 agentNote 往一个更清晰的方向推进：它不是另一套笔记系统，而是让用户挑选的 Obsidian 本地资料，能够带着上下文交给 AI agent，并把成果留回原来的工作空间。

我们在做什么

agentNote 要解决的不是“让 AI 看更多文件”，而是让用户不必反复复制路径、上传附件、粘贴正文，再解释这份资料是什么、为什么此刻需要它。用户在 Obsidian 中选中一份笔记、文件、文件夹或文本，agentNote 生成一个只在本机可访问的分享地址；agent 读取当前内容和背景后继续工作，结论也可以写回 vault。

这意味着知识仍然属于用户的 Obsidian，而不是困在某次对话或某个 agent 里。每一次分享、读取和更新，都是把本地知识真正放进工作流。

为什么今天先做首次使用体验

新用户第一次打开接入台时，最重要的不是看完全部功能，而是尽快完成一次真实交接：接入一个 agent，分享一份资料，然后开始对话。只有这条链路跑通，产品的价值才会被感知。

因此我们在接入台顶部加入三步快速教程。它只承担第一次引导，不应该长期占据熟练用户的工作空间，所以加入“暂时隐藏”，并在关闭后明确告诉用户可以到“设置 → 插件设置 → 使用教程”重新显示。这样既减少首次使用的不确定，也不把教程变成持续打扰。

为什么调整 agent 的更新方式

分享链接的意义不只是把文件路径交给 agent，而是把一次明确、可回看的协作交接交给它。此前默认提示词更倾向于让 agent 直接修改本地文件，这会绕开插件的更新轨迹，也让已分享内容的更新方式不够一致。

今天新增了 PATCH /api/shares/<shareId>：agent 更新一份已经分享的文本或文件时，可以通过这条分享 API 完成。这样更新仍然限定在用户明确交出的对象里，同时会留下本地工作轨迹。默认提示词只写清这一条更新方式；具体任务是否适合、是否需要别的处理，由 agent 结合实际情况判断并向用户反馈。

为什么调整 README 与文档

agentNote 的主要用户仍是中文用户，所以使用说明、产品设计、上架流程等文档继续以中文为主，并配套英文副本。但 Obsidian 社区插件市场的根目录 README.md 需要英文，因此我们将英文 README 作为默认入口，同时保留 README.zh-CN.md 作为完整中文说明。

文档不是为了堆材料，而是为了让不同场景下的人都能快速理解同一件事：这个插件只在本机工作，用户决定交给 agent 什么内容，agentNote 负责让这次交接可读取、可延续、可回看。

今天留下的产品状态

  • 接入台已有可关闭、可恢复的首次使用教程。
  • 已分享内容可通过分享 API 更新，默认提示词已改为说明这一方式。
  • 中英文文档入口已重新整理，满足社区市场与中文用户的双重需要。
  • 0.3.2 已作为 GitHub Release 发布，包含插件安装所需的构建附件。
