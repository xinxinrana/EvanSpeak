产品视觉协作提示词方法论：从产品主张到海报系列

把一个还在形成中的产品想法转成一组可用视觉：先找产品的真实动作，再把自然语言反馈翻译成可执行的视觉约束，最后让链接成为统一的视觉语言。

成型
产品设计AI 图像生成提示词方法论视觉传播

适用场景

用于将一个还在形成中的产品想法，逐步转化为一组可用的 AI 生成视觉。尤其适合产品功能复杂、需要用海报或信息图向用户讲清价值的场景。

本次实践对象是 agentNote：以 Obsidian 为本地文档仓库，通过 s-x 活链接把文本、文件、文件夹及其背景交给不同 agent，并把用户置于调度中心。

一、先找产品动作，不从风格开始

高质量视觉的起点不是“做得科技感一些”，而是回答：用户在产品里真正完成了什么动作？

本次最终收敛为四个可视化动作：

  1. 用户在 Obsidian 中沉淀知识。
  2. 用户将文本、文件或文件夹生成 s-x 活链接。
  3. 用户把链接作为上下文交给不同 agent 或新任务。
  4. agent 读取最新内容，成果再回到用户的知识库或任务中。

每张海报只承担一个动作或一个价值主张：

  • 调度台：用户用 Obsidian 文档调度多种 agent。
  • 分享：在 Obsidian 右键菜单中复制 s-x 链接。
  • 原理图：文档 → 活链接 → agent → 结果写回。
  • 分享多样性：文本、文件、文件夹都能分享。
  • 使用演示：已有笔记只需粘贴链接即可复用。
  • 品牌主视觉：一个活链接让知识成为多 agent 的协作语言。

原则：一张图只让用户“一眼懂一件事”。

二、把自然语言反馈翻译成可执行的视觉约束

用户给出的是判断，生成提示需要把它转译成构图、对象关系和禁止项。

用户反馈可执行的视觉翻译
“脱离了 Obsidian”把 Obsidian 标志和文档仓库放在视觉中心；所有连线经由该中心。
“更明亮一些”暖白背景、淡紫/天蓝渐变、轻阴影；明确排除深色和魔法氛围。
“让人一眼看懂作用”用左到右或上到下的单一流向；用箭头、链条、任务卡与回写箭头代替抽象装饰。
“多用产品图标”agent 使用清晰、彼此区分的产品徽章；图标是角色，不是背景装饰。
“体现复用方便、输入简单”展示真实输入框；只保留一条新任务与少量 s-x 链接，明确不出现长文复制或上传操作。

这比反复说“高级一点”“好看一点”有效，因为它直接改变画面的信息架构。

三、提示词的稳定结构

生成产品海报时，按以下顺序描述，结果更可控：

  1. 用途：海报、功能发布图、原理图或使用演示。
  2. 主张：这张图要让人相信的唯一一句话。
  3. 核心对象：必须出现、且必须能识别的产品元素。
  4. 对象关系：谁发起、谁居中、信息往哪里流、是否回写。
  5. 构图层级：标题区、核心区域、辅助步骤或说明所在位置。
  6. 风格系统：明暗、材质、色板、排版气质。
  7. 精确文案：需要展示的标题、说明、标签，逐字提供。
  8. 限制条件：明确排除会破坏产品理解的内容。

可复用提示骨架：

```text
用途：<海报类型>
唯一主张：<用户一眼应该理解什么>
核心对象：<必须辨认的产品、功能、图标>
关系：<对象 A → 对象 B → 结果；谁是中心>
构图：<标题区、主视觉、辅助说明的位置>
风格：<明暗、色板、材质、品牌气质>
文案：<逐字内容>
限制：<不允许出现的风格、对象、复杂度>
```

四、真实产品画面不是装饰，而是证据

当需要证明功能已经存在时，应把真实截图作为视觉依据，而不是让模型凭空画一个“类似界面”。

本次两个有效方式：

  • 用 Obsidian 右键菜单作为“分享”功能的核心证据，并放大 agentNote: 分享（复制 s-x 链接）。
  • 用 WorkBuddy 的输入框作为“笔记复用”的核心证据，突出只需输入任务和少量链接。

截图在这种海报中的角色是产品证据；渐变、放大镜、流程线和标题只负责引导用户注意它。

五、让链接成为统一的视觉语言

agentNote 的抽象能力是 s-x 活链接，因此它需要被稳定地画成一个可重复识别的“产品符号”：紫色链接 token、链条图标或带链接的卡片。

同一符号应同时出现在：

  • 右键“分享”功能图；
  • 三种分享对象图；
  • 任务输入与笔记复用图；
  • 多 agent 调度图；
  • 品牌主视觉。

这样，用户会逐渐把“链接”理解为 agentNote 的协作接口，而不是普通 URL。

六、迭代时优先改语义，再改风格

推荐顺序：

  1. 先验证产品是否被讲对：Obsidian 是否是中心？用户是否拥有调度权？链接是否看得见？
  2. 再验证信息是否读得懂：流向是否单一？一张图是否只有一个重点？
  3. 最后才统一视觉：明亮度、色板、材质、图标样式、留白。

本次最关键的修正不是某个颜色，而是将“泛 AI 指挥者”改为“Obsidian 文档仓库 + agentNote 调度层 + 多 agent”。这类语义修正会显著提升海报的产品解释力。

七、最终检查清单

生成前检查：

  • 是否只有一个明确主张？
  • 产品本身是否可被识别，而不是被通用 AI 图像替代？
  • 用户是否位于控制关系的起点？
  • 数据或任务的去向和回流是否明确？
  • 真实界面出现时，关键操作是否比装饰更显眼？
  • 文案是否足够少，且可逐字检查？
  • 是否明确排除了深色、魔法感、机器人、泛仪表盘等偏离产品的视觉惯性？

结论

最有效的协作方式是：用户用短句持续校准产品判断，设计执行将这些判断翻译为“主角、关系、层级、限制”四类视觉约束。不要把生成当作一次性出图；将它视为从产品语义到视觉语义的连续收敛过程。

这篇文章回应的问题

产品功能复杂时，怎么用海报或信息图把自己的价值讲清楚，而不是先去追“科技感”。
