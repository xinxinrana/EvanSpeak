# 内容与页面规范

文章以仓库中的 HTML 文件为准。AI 可以直接写 HTML；本地工作台负责打开现有页面、人工精修、写回 HTML 和检查待推送文件，不要求草稿或其他中间格式。

## 路径

| 路径 | 内容 |
| --- | --- |
| `topics/<主题>/notes/<slug>/index.html` | 文章页面 |
| `topics/<主题>/notes/index.html` | 主题笔记列表 |
| `topics/<主题>/index.html` | 主题落地页和笔记篇数 |
| `notes/index.html` | 全站笔记列表 |
| `index.html` | 首页主题数据和右侧笔记链接 |

主题目录固定为 `product`、`ai`、`business`、`system`、`observe`。`slug` 使用小写英文字母、数字和短横线，例如 `a-warm-croissant`。

文章页中的常用相对链接：

| 目标 | 从文章目录出发 |
| --- | --- |
| 站点首页 | `../../../../` |
| 主题页 | `../../` |
| 主题笔记列表 | `../` |
| 另一主题的文章 | `../../../<主题>/notes/<slug>/` |
| 共享文章样式 | `../../../../assets/article.css` |

不要把线上仓库名前缀写入站内相对链接；相同 HTML 应同时适用于本地预览和 GitHub Pages。

## 文章 HTML

现有大部分文章使用 `assets/article.css`，页面主要由 `header.hero`、`article.body` 和 `aside.related` 组成。标题在 `h1`，摘要在 `p.summary`，内容状态在 `span.state`，标签在 `div.tags`。页面 `body` 的 `data-topic` 决定主题强调色。

这是现有文章的常用结构，不是所有页面必须遵守的模板。`topics/ai/notes/feeling-to-phenomenon/` 使用独立样式，并嵌入同目录的 `content.html`；编辑这类页面时应保留其原有结构和相对路径。新页面可以采用适合内容的 HTML 结构，同时保持可读、可访问和可维护。

正文常用 `h2`、`h3`、`p`、列表、引用、`strong`、`em`、`code`。使用表格时，可参考现有的 `div.table-wrap > table`，确保窄屏可横向滚动。图片放在页面目录的 `images/` 或仓库内合适的资源目录，并写明有意义的 `alt` 文本；纯装饰图可以使用空 `alt`。

内容状态描述成熟度，不等于站点可见性。现有页面出现 `萌芽`、`成型`、`待整理` 等状态；不要把状态当作上下架开关。

## 编辑现有页面

1. 运行 `node tools/editor/server.mjs`，在 http://127.0.0.1:8898/site/ 打开本地网站。
2. 复制需要修改的页面 URL，粘贴到 http://127.0.0.1:8898/ 。
3. 在页面中修改文字、链接或图片；修改布局、脚本或特殊页面时使用完整 HTML 源码。
4. 点击“更新 HTML”，检查本地页面，再查看待推送文件并推送。

工作台直接修改原 HTML。对于使用常用文章结构的页面，改动标题、摘要、分类或状态时会同步现有列表信息；特殊页面和复杂结构应手动检查各入口。工作台的编辑预览禁用页面脚本，因此首页等依赖脚本生成的内容应在本地网站 URL 中复查。若 HTML 同时被 Agent 或其他工具修改，工作台会拒绝覆盖，需重新打开页面。

## 新增文章

工作台当前打开和修改**已有** HTML 文件；它不会创建新文章或自动把新页面加入所有入口。新增文章时：

1. 创建 `topics/<主题>/notes/<slug>/index.html`，并在本地网站确认页面和资源路径。
2. 在 `topics/<主题>/notes/index.html` 与 `notes/index.html` 添加文章卡片。
3. 更新 `topics/<主题>/index.html` 的笔记篇数。
4. 在 `index.html` 对应主题的 `notes` 数组中添加标题、提示和链接。
5. 检查文章之间的关联链接，确认没有指向尚未发布的页面。

从 Obsidian 整理内容时，`frontmatter`、内部双链和仅供写作过程使用的说明不应未经核对就公开。保留原意并进行必要的页面排版与链接处理；具体措辞修改由内容任务决定。
